# Research Operations — the disciplines that keep a desk honest

Distilled operating doctrine for an AI-augmented research desk: how conclusions become mechanisms, how infrastructure stays trustworthy, and how findings survive contact with the tape. Each item carries its ruling date; percentages and methods are preserved, personal context is stripped.

## did-we-actually

**Every verdict, plan, or fix must end with a mechanism that fires without anyone remembering — never stop at the artifact.** Pattern (ruled 2026-08-06, fired 4+ times in one session): "did we actually run it / place it / set the tripwire?" reliably finds prose pretending to be a mechanism. The artifact (doc, plan, verdict) feels like completion; the step that ACTS was skipped. Standing three-step, same session, every time: (1) WIRE the specific instance — a pack, cron, queue, or sweep that fires on a date or event; (2) add or extend an INVARIANT so the whole class is machine-flagged and breaches are emailed (reference implementation: desk/pipeline_invariants.py — e.g. R1.7 fix-landed-without-e2e = CRITICAL, RE.6 adjudication-without-same-session-sweep, I8 courted prose-triggers without packs); (3) record the rule as a numbered, dated, attributed line in the PRD (reference implementation: signalos/PIPELINE_PRD.md), which wins over the architecture doc on conflict. Corollary: before ending any turn that produced a verdict/plan/fix, ask "what is the step after this that acts, and did it run?" See: execution-autonomy-ladder, thesis-pipeline.

## codify-agent-feedback

**Framework-level suggestions inside sub-agent DD outputs are validated design hypotheses — codify them into the matcher/detector library at end-of-batch, never leave them as soft notes.** Ruled 2026-05-28/29: a DD agent recommended gating a detector by issuer business-model; one half was implemented same-session, the other sat in the report until surfaced a day later — costing a full session of agents re-deriving "this detector doesn't apply" when a 5-line APPLIES_TO change would have prevented dispatch. How to apply: after all sub-agent DDs land, grep each verification.json for "feed back," "suggest," "improvement," "low-information for," "would be better." Each hit is a framework hypothesis independently validated at runtime. Codify as an APPLIES_TO update, matcher semantic, sister detector, or `must_have_feature` / `anti_features` gate. Implementation cost is usually under 30 lines; value compounds across every future dispatch. See: kg-dispatch-index.

## research-flows-to-ui

**Updating the durable stores and the dashboard is the CLOSING step of every analysis — before the final message, not a later task — and the change must be VERIFIED visible via the API.** Flagged six times across two sessions (2026-06/07); every miss was caught by the principal, not the system. The closing checklist (2026-07-01): (1) new or changed verdict → ledger upsert with alert levels; (2) DD quant → the per-ticker edge-classification record (fv, p, entry band, sizing); (3) any later pass (skeptic/rebuttal/re-audit) that changes sizing or structure propagates to entry plan + ledger + classification — an adjudication living only in a memo is invisible; (4) re-run the scanner (its output is a file the alerts page reads); (5) restart the server if aggregator code changed; (6) VERIFY by curling the aggregate API — never declare done from the write alone. Structural rules: name+verdict live in one research ledger surfaced on the dashboard; new detectors/connectors require a knowledge-graph rebuild (a detector not in the graph is invisible); every entry condition carries a QUANT block (entry level, multiple at that level, base FV, upside at spot and at entry, margin of safety), never prose; every catalyst carries a frozen desk prediction (p_favorable, direction, magnitude, decisive metric, base rate). Durable fix if drift recurs: a heartbeat consistency validator diffing classifications vs entry plan vs ledger. Reference implementation: desk/ui/aggregator.py, desk/data/research_ledger.json, desk/data/catalyst_predictions.json.

## living-decks

**When a watched event resolves, the deck updates and re-ships — the reader artifact never lags the record.** Ratified 2026-09-04: any filing-watch fire, pack grading, gate drain, or band staging appends a dated EVENT ADDENDUM to the name's deck, regenerates the PDF, and re-emails it. Wired automatically into filing-watch fires; called procedurally at every session close-out that resolves a watched item. This extends the adjudicate→stamp→re-email standard from adjudications to all event resolutions. Reference implementation: desk/deck_update.append_and_ship(ticker, headline, body). See: legible-emails, research-flows-to-ui.

## legible-emails

**Every system email routes through the house mailer and meets the legibility standard — the inbox list alone should tell the story of the day.** Ruled 2026-07-30 (first on one alert, then generalized to all). Alerts ARE the product surface; an email the reader must decode defeats within-the-hour response design. The standard, enforced in the mailer (reference implementation: desk/mailer.py — never raw smtplib): (1) subject states the specific event, never the module name ("WAL: new 8-K", not "catalyst event"); (2) facts first — what/when/link before doctrine; doctrine last and labeled; (3) plain language — form codes, detector names, state enums expanded or dropped; (4) stake lines pulled from the live positions cache, never hand-written (a stale hand-written line misreported an order days after its fill); (5) always ship an HTML alternative with bold headers, clickable links, monospace for briefs. New watches must use the mailer.

## ticker-dossier-links

**Every ticker rendered anywhere in the product links to its canonical dossier — all its deep diligence — never a dead string.** Ruled 2026-07-09. One stable URL per ticker (reference implementation: server route /ticker/{sym} → desk/ui/dossier_page.render, fed by the aggregator's ticker_dossier). Dossier sections in order: the edge as "what risk we're paid for" (edge_source taxonomy: FLOW/INFO/VALUE/CARRY/CONVEXITY/EXCLUSION plus a plain-language explainer); "us vs the market" (each frozen call's our_p vs market_p — the gap IS the edge); deep diligence; calibration record; position & trades; briefs; research docs; detector features. Provenance loop: every prediction links to the detectors that generated it, and each detector page shows its full prediction track record and aggregate Brier — forward prediction→detectors, reverse detector→calibrated calls. Backfill provenance when attributable; write "(provenance not recorded)" when not — never invent a detector. Enforce in generators with a tklink() helper; when building any new page that lists tickers, wire the link before shipping.

## poll-positions-first

**Ledger verdicts and entry PLANS are not holdings — poll live account positions before ANY sleeve, concentration, "we hold X," or trim/swap claim.** Two catches: (2026-07-04) courts were told "we hold" names that were unfilled basket plans and resting GTCs that never filled — sleeve-concentration findings, correlation claims, trim-to-fund and tax-harvest angles are all wrong when premised on plans-as-positions. (2026-07-15) a staged instruction VANISHING from the instruction list means it was most likely submitted → live → possibly FILLED, not deleted; misreading the absence produced a re-staged duplicate on a filled starter — an unauthorized add. How to apply: (1) poll positions (or the refreshed positions cache) and state holdings vs plans separately; (2) plans and resting orders count toward the INTENDED-allocation budget (sleeve caps bind forward), only positions toward REALIZED risk; (3) court briefs carry the actual position list, never recollection; (4) absence-of-instruction is itself a positions-poll trigger — check trades + positions before re-staging anything.

## infra-vs-negative

**Classify infrastructure failures distinctly from analytic negatives, and alert on zero-output runs — an outage that looks like a normal bad day runs forever.** Ruled 2026-08-05: a headless grader ran 153 cron jobs over two weeks producing zero grades — an auth outage (cron outside the login session cannot unlock the Keychain; the CLI exited 0 with "Not logged in") wearing the costume of "the model declined to grade." Detected only by a downstream absence the principal noticed. Exit code 0 plus a well-formed response object is not success. How to apply: (1) never let an infra failure (auth/timeout/transport) share an error code with an analytic negative — INFRA is its own class; (2) alert on zero-output runs — "produced nothing N runs in a row" catches what per-item checks miss; (3) log the raw subprocess evidence you already captured; (4) order capped queues by staleness or new arrivals starve the backlog forever; (5) credentials in a file survive cron, credentials in the OS keychain do not. See: research-flows-to-ui, show-graph-validate-output.

## latency-test-before-edge-claim

**A data connector's TRADING edge is a separate empirical question from its NOWCAST value — run an event study on price latency before claiming alpha, and never generalize a single-name null to the method.** Ruled 2026-07-08 (state gaming data parsed weeks before a casino microcap's print): event study n=26 (18 clean) found drift-window CAR statistically identical to placebo (p=0.59), no surprise→return correlation — a clean null. The name was 84% idiosyncratic at 3.4%/day vol; a small monthly revenue surprise cannot clear that noise floor, and all top-12 move days were catalysts. Transferable lessons: (1) nowcast value ≠ trading edge — early numbers sharpen a pre-print fundamental court even at zero price-latency alpha; test the two separately; (2) catalyst-dominated microcaps are the WRONG test case for any operating-signal class; the clean test is a multi-property, low-idiosyncratic-vol operator where one region's print is large and isolable; (3) untested sister names are hypotheses, not nulls; (4) a null kills a bad trade cheaply — measure latency BEFORE sizing. See: nowcast-vs-tape-before-prints.

## gated-source-access-ladder

**When a government/enterprise source blocks default tooling, escalate through a defined ladder — full Chrome fingerprint, then real-browser automation — before falling back to archives or giving up.** Rung 1 (ruled 2026-05-23): a 403 on a target you know exists gets a FULL Chrome fingerprint next — UA plus Sec-Ch-Ua, Sec-Fetch-Dest/Mode/Site, Accept-Language, Upgrade-Insecure-Requests, and a Referer pointing at the landing page for deep-linked PDFs; visit the landing page first to populate cookies. Plain UA-spoofing curl is recognized and rejected. Wayback/mirrors only AFTER the fingerprint fails. Exception (2026-05-30): search engines are an IP-reputation wall — no client-side fingerprint (not even TLS/JA3 impersonation) defeats their 429/202 challenges; the fix is an automation-tolerant engine as fallback backstop (fallback chain shipped: brave → duckduckgo → mojeek; Mojeek's thinner index means the consumer must filter noise; drop brotli from Accept-Encoding on the requests path). Rung 2 (validated 2026-06-16): Cloudflare JS-challenge + session-cookie portals (e.g. Laserfiche WebLink municipal records) yield to driving a real, visible Chrome via Playwright — one session with cookies on, land on the entry page first, click through to capture AJAX-loaded document IDs, and fetch the PDF in-page with credentials included (the Python request context lacks the session cookie). Payoff class: primary entitlement records that settle decisive DD questions (e.g. the marketed sponsor absent from the applicant/owner of record). Encoded 2026-06-17 as a reusable connector + a HIGH-severity sponsor/entitlement-mismatch detector.

## memory-rot-protocol

**Institutional memories rot at typed rates — lessons age well, facts rot in weeks; write perishables as DATED observations and run a weekly perishability-×-age re-verification.** Three incidents in two days (2026-07-05..07): present-tense facts kept asserting themselves after the world moved (a "crashed" commodity that had doubled back; a "pending" merger terminated 7 months prior; "controls still not run" that had run). Root cause: recall discipline without expiry pressure. Three rules: (1) write perishable claims as dated observations — "as of DATE, X" — never present tense; a dated claim goes stale gracefully, a present-tense claim lies; (2) weekly ritual: rank all memories by perishability × age and re-verify the top 5 each morning pass — either re-stamp "re-verified: YYYY-MM-DD" (resets the clock) or fix on the spot (reference implementation: desk/memory_lint.py); (3) docket hygiene: any memory-sourced fact entering an agent docket is tagged for re-verification in the docket itself — memory supplies the QUESTION, never the unverified premise.

## generalizable-market-layers

**Market/demand data layers are built as a generalizable series REGISTRY, never as bespoke per-name watches — and wired into the knowledge graph so any matching issuer dispatches against them.** Ruled 2026-08-10. The desk had already built four bespoke versions of the same pattern (EU production stats, bank call reports, customs imports, public tenders) — each a one-off with no reuse; a market layer serving one name encodes nothing into the product (the knowledge graph). How to apply: a new demand-proxy need adds a SERIES row (plus an adapter if the agency is new) to the official-series registry, declares the issuer features it serves, and lets preflight/dispatch promotion do the rest (reference implementation: desk/official_series.py). Migrate legacy bespoke watches opportunistically, never big-bang. Degraded-loud semantics mandatory: an infra failure never caches as an observation. See: kg-dispatch-index, infra-vs-negative.

## entity-disclosure-planes

**A position's risk drivers are ENTITIES, each disclosing on its own NATIVE plane — watch the entity on its plane, not just the held ticker on the home exchange.** Ruled 2026-07-29 after two same-day failures of the single-plane assumption: a supplier position whose tail risk was its customer filing on Japan's TDnet (the US-filings-only watch was blind to the largest risk driver), and a court that sat on a guide cut disclosed via German ad-hoc six days earlier. Customers, controllers, peers, and regulators disclose on EDGAR, TDnet, AMF regulated-info, EQS ad-hocs, Nordic wire services, KRX, court dockets. How to apply: at STAGING (part of owned-name forward instrumentation), enumerate the position's risk-driver entities from the court record — the kill triggers name them — and add one watch entry per entity on its native plane, with adapters per plane (reference implementation: desk/disclosure_watch.py, hourly). New disclosure → clear email within the hour with the why-line and doctrine attached; forecast/ad-hoc-class documents flagged LOUD. A customer- or controller-side revision re-opens the position's pack BEFORE the position's own print.

## kg-dispatch-index

**The knowledge graph must be prescriptive (a dispatch index), not just descriptive (a catalog) — every detector and source declares APPLIES_TO, and the orchestrator queries the graph at dispatch time instead of hardcoding lists.** Ruled 2026-05-29: a top-30 IPO run missed existing defense/energy-budget sources on two obviously-exposed issuers because each module lived wherever it was first built, the dispatch template hardcoded its detector list, and no coverage check ran. How to apply: every new detector/source exports an APPLIES_TO dict ({sic_codes, sic_prefixes, issuer_features, asset_classes, applies_universally, kind, summary, verification_question}) — asset class is hard scope, non-universal modules match on SIC/feature overlap; the orchestrator calls relevant_for_issuer(profile) and uses whatever returns; pre-flight always runs validate_coverage(prompt, issuer) alongside factuality validation, flagging graph-applicable nodes absent from the prompt. Any source declaring APPLIES_TO becomes auto-discoverable across verticals with no bridge files. Reference implementation: knowledge_graph/dispatch.py, build_knowledge_graph.py (static dispatch_index export). Retro-test: the coverage check flagged exactly the three nodes the principal had surfaced by hand.

## show-graph-validate-output

**Show the LLM the whole applicable dispatch index and let it select; move determinism to an OUTPUT-side coverage validator — and validate the query's kwarg KEYS, not merely that a source was invoked.** Ruled 2026-06 (two lessons). First: never pre-filter the detector menu with a keyword scanner — it is strictly dumber than the agent it gates and silently subtracts options (an agent can't pick what it never sees); inlining the full scoped index costs ~1.7k tokens. Pattern: AVAILABILITY (full index in the prompt) + SELECTION (agent declares issuer features and, per applicable item, maps a query or records an explicit decline) + DETERMINISM relocated to verification (re-derive applicability from the union of agent features and a keyword-net backstop; flag anything neither dispatched nor declined). Second: coverage ≠ query quality — a source can be "dispatched" with a structurally-guaranteed-empty query (querying a defense budget index by contractor name when it indexes program elements), letting the agent substitute reasoning for measurement. Fix: WEAK_DISPATCH_RULES requiring meaningful kwarg keys per source, plus per-source DISPATCH_NOTES query-discipline lines rendered inline. When auditing a run, a clean coverage report is NOT sufficient — check that high-value sources were queried on the right key. Reference implementation: verticals/public_co/kg_index.py (dispatch_block, coverage_gaps).

## auto-adjudicate-on-completion

**Completed courts get adjudicated immediately and unprompted — the ADJUDICATE queue is work owed, not a display.** Principal directive 2026-08-08. When red and blue briefs are filed and a case reaches ADJUDICATE, the session processes the whole batch at the next opportunity without being asked: verdict + edge classification + resolution pack + queue→DONE + any staging, in one pass. A sitting adjudication queue is a pipeline stall that blocks the decision-maker. The generator-never-grades-itself invariant is preserved — adjudication stays with the session intelligence, never the runner that dispatched the benches; "automatic" means unprompted, not self-graded. Pitch docs follow, prioritized by decision-relevance (held positions and live instruments first). See: did-we-actually, court tiers.

## escalate-on-decisive-findings

**When a load-bearing finding fires (ELEVATE/EXCLUDE/RED/SELL), re-verify it with a context-rich, higher-intelligence pass BEFORE acting — and make that loop structural, failing CLOSED on every path.** Ruled 2026-06 across three incidents. Why: the cheap high-recall pass is structurally blind to (1) dropped context — extraction severs a quote from the table/slide that frames it — and (2) mis-bound subjects — the case wired to the wrong trial/entity makes every comparison an artifact read as lying. More guards on the cheap pass can't fix context/binding errors. How to apply: gate by decision-weight, not volume — a case has ~50 claims but only 0–4 can flip the call, so escalate only those; restore the full source frame around the flagged quote; re-check binding (divergence on ≥2 independent identity axes = wrong subject, not a liar); allow "no signal" — CONFIRMED requires quoting the contradicting authority; absence of evidence is never confirmation. Structural enforcement (the loop fails OPEN when discretionary — demonstrated twice): verification is a pipeline STAGE with no skip-path, spawned by the same harness as the finder; sub-agents emit structured flags ({claim, why_load_bearing, needs_verification, confidence}), never prose the orchestrator must hunt through; "load-bearing" is a mechanical predicate; an output-side validator asserts every needs_verification flag has a matching verdict, else the report downgrades to PROVISIONAL. The guarantee is path-dependent: any decisive verdict from an ad-hoc screen outside the pipeline is PROVISIONAL until a paired adversarial pass clears it. Cross-vertical pattern, not domain-specific. Reference implementation: verticals/public_biotech/verify_finding.py (verdicts: CONFIRMED / FINDING_WITHDRAWN / M_MISBOUND / BENIGN_DISCLOSED_CHANGE / NEEDS_MORE_M; a mis-binding blocks the call pending rebind).

## radical-honesty-publishing

**Publish with radical honesty, bucketed by liquidity — full levels only on liquid names, price triggers never on thin names, and entries published means exits published forever.** Set 2026-07-23 around the desk's first public content piece; the operator owns marketing and tone, the desk supplies verified content only. The risk sort: (a) liquidity — a disclosed ladder at ≤~1% of ADV is harmless color; at 5–10%+ it is a fill-degradation map (one disclosed bid was 12% of its tape); (b) trigger type — FUNDAMENTAL tripwires (cRPO, backlog, guidance-held) cannot be tape-painted and are always publishable; price triggers on thin names are shake-out manuals; (c) instrument maturity — positions are cheap to disclose, but live unvalidated machinery is the actual edge and dies if published pre-graduation (the counterparty can close the surface). How to apply: liquid names get full honesty including levels; thin names get position + thesis, never live levels; fills disclose after-the-fact (T+days keeps all the credibility, none of the microstructure cost); bullish posts push price away from resting bids — accept it or post after fills; the ONE-WAY DOOR: the brand dies on the first quiet exit; every artifact ships the standard disclaimer + position disclosure (reference implementation: desk/reports/DISCLAIMER_SNIPPET.html).

## productize-full-menu

**A surface destined to be a product presents the FULL option menu with objective costs and scores fit to a configurable profile — the operator's doctrine is a lens, never a baked-in filter.** Ruled 2026-07-10 ("we're trying to productize this, not just make it for me"). Template: the disaster-planner playbook shows every mitigation per scenario — protective puts, put spreads, collars, tail-risk/long-vol funds, managed futures, exchange funds, trims, real-asset ballast, duration hedges, credit lines, insurance, secondaries, accept — each costed from the account's real exposures; a profile block (net_buyer / uses_leverage / premium_selling_allowed / decumulating / concentrated_low_basis) drives only a Fit badge (an index hedge reads "Situational" for a net-buyer accumulator but "Core hedge" for a levered decumulator; collars read "Blocked here" only when premium-selling is off). This recasts prior house doctrine (no index insurance for net buyers; no premium selling in taxable) as profile-conditional scorer INPUTS, not universal rules. Keep the house "our read for this profile" as a labeled recommendation alongside the menu — opinion is fine contextualized, wrong when it hides options. Reference implementation: desk/disaster.py.

## transmit-false-write-rail

**Every order any session stages through the broker API sets transmit=False — the human clicks Transmit — except inside principal-ratified envelopes; live transmit from code is otherwise forbidden until the autonomy ladder's Rung 1 is earned.** Rail history: 2026-07-28 the Gateway's Read-Only API was turned off to enable the "AI order you just click" rail — staged orders sit untransmitted until the operator clicks. Rung 1 (live transmit) requires beating market Brier over n≥20 + TCA + integrity weeks + a shadow month. The hard guarantee moved from CONFIG to DISCIPLINE: any code path touching placeOrder is a court-reviewable change, not a refactor. Untransmitted orders DIE with the staging client's disconnect and are visible only in the desktop terminal — the click-rail requires it running, else re-lock read-only. Ratified exception #1 (2026-08-21): envelopes ratified by the principal in chat, registered with origin signalos_desk+principal, and executed by the principal-run runner may transmit live — the human trigger moves from per-order to per-campaign; kill switches are a halt flag, a halt file, or deleting the registry entry. Foreign agents get NO envelopes (load-time origin refusal — an outside agent transmitted 24 confabulated-price orders 2026-08-20), and the assistant registers and builds but never invokes live execution. Ratified exception #2 (2026-09-02): an into-print guard auto-cancels resting BUY GTCs on US stocks within ~3 days of the next earnings print (sells/trims and deliberate ride-the-print intents exempt); every auto-cancel is recorded and emailed as an action taken — wrong-early is safe, restage post-print. Reference implementation: desk/envelope_runner.py, desk/data/envelopes.json. See: resting-order-into-print.

## scheduler-exhaust-channel

**Appointment/reservation businesses leak utilization through public booking-slot scarcity — a physical, hard-to-fake, free alt-data channel that leads reported volume by 0–1 quarters; treat any new instance as PAPER until it beats consensus through a graded print.** Built 2026-07-23. Metrics: days-to-next-slot, %same-day, walk-in wait minutes. Stack: a generic framework (PanelSpec; blocked = MISSING, never zero; manual-CSV fallback), a first live instance (12 metros × two national lab chains, weekly cron), a candidate census (415 names: 7 yes / 18 indirect / 390 no), and a KG channel node with APPLIES_TO so it dispatches like any source. Banked findings (dated — re-verify before relying): one metro was a 49% JV booking separately that does not consolidate into the issuer's volumes → structural no-coverage, not scarcity; the first sample showed a near-saturated network, so the signal is DELTAS (a metro slipping same-day→+5 days) and walk-in integers, not levels — v1 is a directional nowcast input, not a standalone consensus-beater. Gates: PAPER until graded at the October prints against four frozen calls (dated — re-verify before relying). Next instances require confounder cross-checks (hiring-velocity vs capacity); decline honestly where the exhaust belongs to a channel that can't separate share from traffic. Reference implementation: desk/scheduler_exhaust.py, desk/lab_scheduler_panel.py. See: latency-test-before-edge-claim, radical-honesty-publishing (unvalidated machinery stays private).
