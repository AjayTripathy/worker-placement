3 · The dispatcher — three-ring open-set selection

Input: an issuer profile {sic, asset_classes, features}. Output: the detector subset that applies, with a pre-flight coverage validator (did every fire-able detector get considered?) and output-side validation (kwargs and verdict schema checked, because the selector is a model).

Ring 0 — vetted atlasDetectors carrying a formal APPLIES_TO contract (164 today, table below). Deterministic match on SIC prefix / issuer feature / asset class; applies_universally for the always-on forensics.
Ring 1 — alias + recall floorNamed-but-uncontracted detectors matched on the verification attribute, not subject tokens (the OSHA 46→2 over-fire fix). Gate on attribute + referent type.
Ring 2 — agent-inventsNo existing detector fits: the agent drafts one, runs it sandboxed, and it enters the atlas only through gated promotion. How the atlas grows.

5 · What the verdicts feed

Detector fires → two-mode diligence (claim verification + first-principles disconfirmation) → independent court + red team (generator never grades itself) → edge classification with kill triggers → frozen calibration calls (detector-linked, graded at the print — an instrument earns trust empirically or dies) → entry plan (envelopes; the principal places) → the desk UI on :8765. Composition doctrine: narrow high-precision detectors compose by union, never weighted average — comprehensive scores overfit.
