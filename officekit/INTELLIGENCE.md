# Proposal — Intelligence in Onboarding & Strategy Building

Companion to [PRD v1.2](PRD.md) and [ARCHITECTURE v1.1](ARCHITECTURE.md) · v1.3 · 2026-09-04 · status: **ALL THREE QUESTIONS RATIFIED — agent origin shipped (AI-0 in-tree); unified agent layer; retain-everything-tenant-contained**

## Why now

The deterministic pipeline is real but has hit its honest limits in exactly two places:

1. **Onboarding** — the form works for people who know their tickers and their goals. Real users have PDFs, screenshots, "about 400k at Fidelity, mostly index funds," unknown symbols the FUND_MAP doesn't cover, and goals they haven't articulated. The INTAKE_AGENT.md contract already *specifies* the agent that solves this — it just isn't wired into the product.
2. **Strategy building** — the mandate machinery (two doors, origins, adoption) is shipped, but the *content* is static: a 20-entry library, generic "Our read" prose, hand-authored scenario probabilities, and no reasoning connecting a client's specific goals/profile/concentration to which strategy deserves adoption. That reasoning layer is precisely what the PRD calls the risk officer's tier-2 job.

The thesis: **intelligence is a proposer, never an author of record.** Every agent output enters the system through an existing contract (answers JSON, strategy decision + origin, scenario overlay), gets validated deterministically, and — where it makes a claim — becomes a gradeable record in the learning ledger. This is the desk's "generator never grades itself" doctrine applied to the product.

## Architecture principles

1. **Intelligence is a plugin tier, not core.** The core package keeps its zero-dependency, offline, never-phones-home guarantee. Intelligence ships as `officekit[ai]` (the `anthropic` SDK as its only dependency). Tier-0 users bring their own credentials — and, per the BYOM ruling, their own **models**: `models.json` (contract #10) maps role slots to providers, each referencing its key by env-var name (never the secret); `ANTHROPIC_API_KEY` + Anthropic is only the zero-config default. The hosted tier runs it managed. No usable slot → the deterministic paths keep working unchanged, and every AI affordance simply doesn't render.
2. **Agents emit contracts, not state.** The intake agent emits **answers JSON**; the strategy advisor emits **proposed decisions with origins**; the classifier emits **suggestions the human confirms**. Nothing writes the balance sheet directly; `validate()` remains the gate; every mutation still flows through `build_from_answers` / `mandates.*`.
3. **A new origin source: `agent`.** **RATIFIED 2026-09-04 and shipped**: the mandate trail grows `{source: "agent", ref: <agent_call record id>, date}` alongside `principal` and `scenario` (schema-validated). `mandates.queue_agent_proposal` enforces queue-for-adoption in code — it can only file `considering` and never touches an existing status. This closes PRD open question 1: automated sources queue, humans bind.
4. **Every claim is a frozen call.** Agent-personalized scenario probabilities, strategy-fit arguments, and classification confidences are recorded to the learning ledger at emit time (new record kind: `agent_call`), so agent calibration is graded exactly like scenario predictions. An agent whose Brier record rots gets its outputs demoted — the honest-broker loop.
5. **Never fabricate, mechanically enforced.** The agent contracts already say it (confidence tags, "goals come from the user's mouth"); the plugin enforces it: structured outputs (`output_config.format` / `messages.parse()`) so responses validate against the answers schema at the API layer, numbers cross-checked against source documents where present, and anything unverifiable tagged `assumption` before intake will accept it.
6. **Advice posture unchanged.** The agent explains, drafts, and scores through the existing lens-not-filter framing; it never says "buy X." Sample subassets stay labeled as expressions, not recommendations. The read-only / never-places-orders line is untouched.

## The four capabilities

### I1 — Symbol classification fallback — **SHIPPED 2026-09-04**
Unknown tickers currently pool into "individual stocks" silently-ish. With the plugin: unknowns go to a small model (Claude Haiku 4.5 — classification is its job description) with strict structured output `{category, style, confidence}`; low confidence or any failure falls back to today's behavior. Suggestions render as a **confirmation step** ("VTEB looks like municipal credit — accept?") rather than silent writes, and confirmed mappings append to a local `fund_map_learned.json` so each classification is paid for once. This also seeds the community FUND_MAP via the OSS repo.

### I2 — Conversational onboarding (the intake agent, productized) — **SHIPPED 2026-09-04** (serve chat panel + `python3 -m officekit_ai.intake_chat`)
A chat panel beside the onboarding form (serve app) and an `officekit init --chat` mode (CLI). The agent runs the INTAKE_AGENT.md contract live: accepts freeform descriptions, pasted statement text, and uploaded PDFs (document blocks — the API reads PDFs natively, no OCR pipeline to build); asks for what's missing — goals especially, which forms are bad at eliciting; and emits answers JSON that **fills the form fields visibly** rather than submitting behind the user's back. The user reviews the populated form and clicks the same "Build my office →". Model: Claude Opus 5 (default per current guidance), adaptive thinking, structured output = the answers schema. The existing leak/validation tests extend to agent-produced answers.

### I3 — Strategy advisor (the risk officer's first real job)
Three faces, one engine, all consuming the model the pages already compute (balance sheet, exposures, scenario results, goals grid, decisions + origins):

- **Draft-a-strategy**: the principal describes intent ("I want Japan value exposure, small, courts pending") → the advisor drafts the full card — title, desc, subassets, target %, fit argument against the profile and goals — and files it via `create_adhoc` with an `agent` origin, status `considering`, **queued for the human to confirm or edit**.
- **Personalized reads** (per the Q2 ruling, these run the unified advisor directive — plane-2 personal context loaded, never a separate prompt stack): the generic "Our read (Accumulator)" prose per scenario card becomes client-specific — arguing from *this* balance sheet's concentration, *this* goal grid's SHORT cells, *this* tax posture. Rendered with a visible "agent-drafted" tag; the generic prose remains the no-key fallback.
- **Adoption briefs**: when a mitigation is a click away from adoption, the advisor writes the one-paragraph case for and against — the tier-1.5 bridge between the deterministic lint (which stays Phase-3, non-AI) and the full allocation-court agent.

### I4 — Courtkit-lite — **SHIPPED 2026-09-04** (Q6 ratified) + probability personalization (later)
**Q6 ruling**: users generate their OWN adjudications — a verdict only means something in the context of the strategy that convened the court — and connected tenants exchange two-way (send up, read down), building cross-tenant adjudication intelligence over all equities; every shared record carries strategy + office + date. Shipped as `officekit_ai/court.py`: RED/BLUE benches + adjudicator composed from the shipped court doctrine (plane-2 gated) through the BYOM `bench`/`adjudicate` slots; **U2 tier order enforced at runtime** (adjudicator never weaker — raises; equal tiers stamped `flat_tier`, unrankable BYOM `unranked`); every call a frozen `agent_call`; the record is contract #11 (adjudications.jsonl), with an exchange allowlist that carries tickers by design but never sizes — a separate sanctioned channel from the learning ledger. Honest limitation stamped on every verdict: LITE courts have no live connectors — load-bearing numbers land in an explicit unverified work queue, and the flagship desk keeps its full evidence-pack courts (grading LITE against them is the U3 diff). Live smoke passed: a flat-tier Opus court on VTEB-for-a-2036-college-goal caught the perpetual-fund-cannot-defease-a-dated-liability mismatch and routed it correctly through the response taxonomy. Probability personalization (scenario `p` overrides from client facts) remains the later half of I4.

## The unified agent layer (Q2 ruling, 2026-09-04)

**Ratified: there is no "substitute" advisor.** One agent architecture serves every tenant; the desk is its flagship install, not a special case. The desk's existing agents — the quant analyst's two-mode diligence, the court tiers, the watch/escalate discipline — get *unified into the product*: their directives, plans, and memory become the shipped intelligence layer, and end users bring their own models to run it. What the desk has that a user doesn't (Fable-tier adjudication, private connectors, years of accumulated doctrine) becomes **configuration and data, never a fork**.

### The three memory planes

An agent's knowledge separates into three planes, with different shipping rules:

1. **Generic doctrine — ships.** The detector taxonomy, artifact catalogs, court tiers, response taxonomy, edge classification: the accumulated microstructure knowledge IS the product corpus, versioned and upgradeable like code. Extracting it from today's entangled memory requires the same audited de-personalization discipline the engine extraction used.
2. **Personal context — never ships as content, ALWAYS ships as structure.** Shipped as **contract #9** (`personal_context.json`, SCHEMAS.md): onboarding writes the empty skeleton, `require()` gates every advise path, `check_exclusions` enforces ticker/issuer exclusions in code, and `officekit link` pushes it to the hosted tier envelope-encrypted (agents there need the same gate; the learning store never sees it). Principal ruling: **every shipped agent must have personal context built in** — a first-class, mandatory tenant overlay (constraints like employment exclusions, tax posture, household boundaries, doctrine rulings) that every directive is written to consume. The slot ships empty and required, not optional: an agent that hasn't loaded its tenant's personal-context document refuses to advise, the same way the scenario engine's `requires` gates decline to fire without data. Our desk's personal context (IBM exclusion, tax map, household) is simply one tenant's instance of it.
3. **Tenant-accumulated memory — grows per tenant.** Each user's rulings, feedback, and graded calls accumulate in their own office, the same way the desk's did. This is the retention moat: after a year, an office knows *its* principal's doctrine.

Leak tests extend to the shipped corpus: plane 1 is published only after the same personal-string audit the renderers get.

### Bring-your-own-model = role slots, not free choice

**Slot config SHIPPED 2026-09-04** as `models.json` (contract #10, `officekit_ai.models`): slots → provider + model, providers as a registry (`anthropic` built in, others plug in), credentials referenced by env-var name with key material in the document rejected loudly. Court doctrine binds roles to capability, not vendors: the generator never grades itself; the adjudicator is never weaker than the bench; decisive findings escalate. So the slots are `classify / intake / bench / adjudicate / verify` — each declaring a minimum contract (schema-constrained outputs) and ordering constraints the harness enforces (adjudicator ≠ generator and not a weaker tier; the ordering checks land with U2 when bench/adjudicate activate). Enforcement of quality is by measurement, not policing: every call is a graded `agent_call` record, so a weak model in a load-bearing slot shows up in the tenant's own calibration ledger and demotion is mechanical.

### Input-coverage fingerprints

Desk agents lean on connectors users won't have. A court running identical directives on poorer inputs grades worse for reasons that aren't model quality — so every `agent_call` stamps which data planes were live (`coverage: [edgar, live_prices, …]`). Grading and cross-tenant learning compare like with like, and a tenant can see what a missing connector costs them in Brier.

### Consequences

- **AI-3 is rewritten**: the strategy advisor is not a separate prompt stack — it is the unified advisor directive, which the desk runs with the best models, full coverage, and the deepest plane-3 memory.
- **The glass-box question (PRD Q6) partially dissolves**: users running real courts locally generate their own adjudication refs; our published adjudications become a reference corpus to diff against, not gospel to consume.

## What this deliberately does not do

- No agent ever executes, sizes, or transmits anything — mandates it proposes still queue.
- No agent writes to `balance_sheet.json`, decisions, or the ledger except through the typed contracts above.
- No always-on background agent in Tier 0 — every invocation is user-initiated (a chat turn, a classify click, a draft request). Standing/scheduled intelligence is a hosted-tier (Tier 1) concern.
- The deterministic lint stays deterministic. Intelligence narrates and argues; it does not replace rule checks that code can do.

What is structural NOW, because it cannot be retrofitted:
   1. Every retained artifact — uploaded PDFs, agent transcripts, answers drafts — is a **tenant-scoped, envelope-encrypted document** in the same store as the balance sheet (new artifact types get a `doc_type`, never a new bucket).
   2. Application logs and traces carry record **ids, never contents** — a CI-testable invariant in the leak-test family.
   3. Deleting a tenant deletes the corpus **as a unit**; backups age out on a fixed window.
   4. `officekit export` includes the retained corpus — the glass-box counterweight: we keep everything, and so can you.
   5. The hosted tier calls the API under our org key on standard commercial terms (inputs/outputs not used for training); zero-retention at the API layer stays an open dial because our own store already retains what the product needs.

   Retention *durations*, disclosures, and opt-outs are then policy parameters over an already-contained corpus — deferrable honestly. AI-2 is unblocked for the hosted tier.
